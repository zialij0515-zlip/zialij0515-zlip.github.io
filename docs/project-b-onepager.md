# B 项目讲解一页纸 · 华夏基金养老「自助问数助手」（WrenAI）

> 用途：面试前翻一遍就稳。对应 `B项目_PRD.md` / `B项目_语义层MDL与指标口径.md` / `B项目_指标测试问题清单.md`。

## 一句话定位
让不懂 SQL 的业务 / 投研 / 客服，用大白话问数据库要数，且**同一指标谁问口径都一样**。

## 大白话 / 术语对照
- **大白话**：业务打字问"养老规模多少"，秒出数，不用等数据团队排期。
- **术语**：GenBI（生成式 BI）/ Text2SQL 应用；WrenAI（开源语义层问数框架）+ PostgreSQL 合成数据 + 阿里百炼 Qwen。
- **产品内核**：语义层（Semantic Layer）治理——把 6 个核心指标口径锁死，根治"同指标不同数"（企业级数据治理痛点）。

## 架构（一句话）
提问者 → Wren UI（localhost:3000）→ Wren AI Service + 语义层 MDL（SQL pairs 黄金示例）→ PostgreSQL（5 表 ~12 万行）→ 答案 + 图表回传。

## 操作步骤
1. **造数据底座**：Python 造 1 万模拟投资者 + 持仓/订单/定投 ≈12 万行，灌 PostgreSQL（脱敏、口径自定）。
2. **起环境**：Docker 起 WrenAI 连 PG；选百炼 Qwen（WrenAI 0.29 强制 `json_schema`，DeepSeek 不支持会崩，OpenAI 要充值+代理）。
3. **建语义层**：5 张表（2 维 + 3 事实）建模 + 连关系，关键列补中文枚举描述。
4. **锁指标口径**：6 指标各写"黄金 SQL"（如养老规模 = `SUM(market_value) WHERE fund_type='养老' AND 最新日`），做成 SQL pairs 进语义层。
5. **跑 20 题验收**：逐条问、对账、统计三率。

## 难点 / 技术点
- **模型选型坑**：WrenAI 0.29 强制 `json_schema` → DeepSeek 报 400 / OpenAI 报 429 → 换百炼 Qwen 一个 Key 通吃 LLM+Embedding，零成本跑通。
- **视图非一等公民**："Save as View" 只是 UI 收藏、不进问数检索（命中率 0%）→ 改用 SQL pairs 真正进生成链路。
- **中文枚举映射**：LLM 把 `养老` 猜 pension、`进行中` 猜 active、`申购/赎回` 猜 subscribe/redeem → 语义层锁中文枚举 + CASE WHEN 解决。
- **复合口径**：渗透率分母、收益率口径等只能 PM 手定义，模型猜不来。

## 亮点
- **产品思维 > 炫技**：不卷"把 SQL 写对"，治理语义层根治数据治理痛点。
- **闭环可验证**：治理前 20% → 治理后 90%（+70pct），形成"治理前→治理后"硬证据；连"视图 0% 命中"都转化成"证明语义层刚需"的论据。
- **诚实边界**：合成数据、行级权限是设计项、2 处瑕疵根因全明示，不掩盖。

## 量化成果（治理后第三轮）
- SQL 生成率 **100%** / SQL 正确率 **90%** / 答案合理率 **90%**。
- 2 题瑕疵（非 bug）：#4 近义问法歧义、#10 相对时间语义。

## 面试 3 分钟话术（要点）
"我没去卷把 SQL 写对，而是用 WrenAI 语义层把养老业务 6 个核心指标口径锁死——无论谁问口径都一致。过程中定位并解决了 WrenAI 要求 json_schema 而 DeepSeek 不支持导致整体失败的关键坑，最终用国产百炼 Qwen 零成本跑通，治理后准确率从 20% 提到 90%。"
