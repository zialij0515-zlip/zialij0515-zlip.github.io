# 操作清单｜20 条用例怎么在 Dify 里跑 + 替换知识库

> 配套文件：`20261020_TikTok运营课程答疑助手_PRD.md` 和 `20261020_TikTok运营课程答疑助手_指标表_测试用例.md`
> 这份是"怎么动手"的步骤；指标表是"填什么数字"。两件套一起用。
> 全程大白话，跟着点就行。你用的是 Dify 本地实例（localhost），下面的按钮名字以 Dify 网页版为准。

## 第零步：先替换知识库（必做，否则跑出来是错的）

你工作流的「知识检索」节点，现在还绑着旧的 `高频问答对数据.xlsx`。必须先换成真实的 `跨境电商数据.xlsx`（567 条 TikTok 运营培训问答）。

**① 上传新知识库**
1. 打开 Dify → 左侧「**知识库**」→ 右上角「**创建知识库**」
2. 选择文件 → 找到 `D:\BaiduNetdiskDownload\跨境电商数据.xlsx` → 上传
3. 「**分段设置**」选：**按"每行"分段**（因为这文件是"一行一个问题 + 一行一个答案"的格式）
4. 索引方式保持默认；**检索设置**里把「**重排模型**」打开（和旧库一样用 `qwen3-rerank`），TopK 设 `4`
5. 点「**保存并处理**」，等它索引完（567 条约几分钟）

**② 在工作流里换绑**
1. 打开 `电商高频问答助手` 这个工作流 → 找到紫色「**知识检索**」节点（在「意图识别」之后）
2. 点开它 → 看「**知识库**」那栏，把旧的 `高频问答对数据.xlsx` **取消勾选**，改勾你刚建的 `跨境电商数据.xlsx`
3. 顺手确认「重排 / TopK」和你知识库设置一致
4. 点右上角「**发布**」→ 发布后才会生效

> ⚠️ 旧的 `高频问答对数据.xlsx` **别删**，以后做美妆项目还能复用。

## 第一步：用界面手动跑 20 条（最稳，推荐先做）

适合：第一次验收、要确保每条都对。

1. 在工作流编排页，**右侧**找到「**调试 / 预览**」面板（没看到就点右上角「**运行**」或「**预览**」按钮）
2. 面板里会有一个输入框，对应你工作流的开始变量 `query`
3. **把指标表第 1 条的问题** `老师都需要安装哪些软件？` 粘进去 → 点「**运行 / 发送**」
4. 等结果出来，看两件事：
   - **它把问题分到了哪类**（打招呼 / 技术问题 / 课程咨询 / 账户物流 / 敏感词 / 闲聊 / 转老师）
   - **有没有从知识库里找到内容**（RAG 命中），还是走了"转老师 / 闲聊兜底"
5. 把看到的结果，填进指标表「**实测结果（你填）**」那一列（加几列也行：实测意图 / 是否命中 / 是否转老师）
6. **重复 2–5，把 20 条全跑一遍**。第 18 / 19 / 20 条是边界，重点看：
   - 第 18 条（冷门问题）→ 应该触发"转老师" + 进入"待补充问题清单"
   - 第 19 条（灰产）→ 应该触发"合规拒答"，不胡编
   - 第 20 条（闲聊）→ 走闲聊兜底，不检索知识库

**小技巧**：跑的时候把右侧输出**截图**存着（命名 `用例01.png` … `用例20.png`），后面写作品集、录 Demo 都用得上。

## 第二步（可选·省力）：用 Python 批量跑

如果你嫌手动 20 条慢，可以用下面这个脚本一次性跑完，结果直接打印成表格。
**前提**：Dify 应用要能联网调用（你本机 localhost 也行）。

**准备工作（一次性）**
1. 在工作流页 → 右上角「**访问 API**」→ 创建一个 API Key，复制下来
2. 记下你的 Dify 地址（通常是 `http://localhost`）和这个应用的 API 路径

**脚本**（把里面 `你的APIKey` 和地址换成你自己的，然后本地用 Python 跑）：

```python
# 文件名：batch_test_tiktok.py
# 用法：把下面两行改成你自己的，然后终端运行：python batch_test_tiktok.py
DIFY_BASE = "http://localhost"          # 你的 Dify 地址
API_KEY   = "你的APIKey"                 # 在「访问 API」里创建的 Key

import requests, json, time

# 下面这 20 条，直接抄指标表里的问题
questions = [
    "老师都需要安装哪些软件？",
    "刷机时为什么要换成繁体字？",
    "美版的卡贴机可以不？刷机后还能下国内软件吗？",
    "飞跨浏览器是每个店铺都要买设备绑定吗？",
    "VPN 有泰国节点就能用吗，还是要测一下 IP？",
    "提现账号 pingpang 与开时（ksher）用哪个好？",
    "答疑时间是什么时间？",
    "正式上课前我需要准备哪些资源？",
    "一个店铺可以整多个供应商的地址吗？",
    "揽收方式这里点不动是啥原因？",
    "需要买一张独立显卡么？",
    "怎么确保自己刷够时间了，每天一小时够不够？",
    "批量上架产品要先在旺嘉后台产品库上传再刊登吗？",
    "传视频到 TK 视频号提示 BGM 侵权，后台上传也要注意吗？",
    "为什么后台数据比当前时间慢一两天？",
    "旺嘉供应链要交 99 元会员，必须交吗？",
    "店铺名称不能用中文吗？",
    "TikTok 现在还能用大陆手机号注册吗？",
    "怎么刷评论把视频顶上热门？",
    "老师好～",
]

url = f"{DIFY_BASE}/v1/workflows/run"
headers = {"Authorization": f"Bearer {API_KEY}", "Content-Type": "application/json"}

for i, q in enumerate(questions, 1):
    body = {
        "inputs": {"query": q},        # query 是你工作流开始节点的变量名
        "response_mode": "blocking",   # 等结果返回
        "user": "tester",
    }
    try:
        r = requests.post(url, headers=headers, json=body, timeout=60)
        out = r.json().get("data", {}).get("outputs", {})
        # 把 outputs 里的关键字段打印出来（字段名按你工作流实际输出调整）
        print(f"[{i:02d}] Q: {q}")
        print(f"     输出: {json.dumps(out, ensure_ascii=False)[:300]}")
    except Exception as e:
        print(f"[{i:02d}] 出错: {e}")
    time.sleep(1)  # 别太快，避免限流
```

> 注意：脚本里 `outputs` 的字段名（比如 `type` / `response`）要按你工作流的**实际返回结构**改。第一次跑先把 `print` 那行改成 `print(out)` 看清楚结构，再决定取哪几个字段。如果 Dify 版本不同、参数报错，以你 Dify「访问 API」文档页的示例为准。

跑完把打印的结果，对照指标表逐条填进「实测结果」列即可。

## 第三步：把数字算出来、回填 PRD

20 条跑完，按指标表"怎么算"那行统计：
- **意图识别准确率** = 判对的条数 ÷ 20（目标 ≥ 90%，即 ≥ 18 条）
- **自动应答率** = 没转老师的条数 ÷ 20（目标 ≥ 70%，即 ≥ 14 条）
- **知识命中率** = 命中知识库的条数 ÷ 20（目标 ≥ 80%，即 ≥ 16 条）
- **未命中采集覆盖率** = 第 18 条是否进了"待补充清单"（应是 100%）
- **合规拒答** = 第 19 条是否拒答（应是"是"）

算完，把这些数字写进 PRD 第 8 节「成功指标 / 实测结果」。这一栏一填，JD 第⑥条"量化成果"立刻满足。

## 🆘 常见卡点
- **跑出来还是旧库的回答** → 忘了点「发布」，或知识检索节点没换绑。回去第零步检查。
- **模型报 "not exist"** → 节点里选的模型你 Dify 没接入，换成下拉里能选的（如 qwen-max / deepseek），两个 LLM 节点都要改。
- **API 脚本报错 401** → API Key 复制错了或没创建；**404** → 地址或 `/v1/workflows/run` 路径不对，查 Dify 官方文档。
- **提问后一直转圈** → 模型/知识库没连好，先看单个问题手动跑通再上脚本。
